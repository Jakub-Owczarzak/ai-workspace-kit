## Intent Anchor

**Goal:** Make the workspace kit a complete AI-native workflow that combines the playbook with what we built:
add what is missing, keep what works, upgrade what is close. Reusable across projects of any size.

**Success criteria (measurable):**

- Every new control can be switched on or off by a workflow profile (`solo`, `team`, `org`) plus per-control
  overrides, and the defaults for `solo` change nothing for PRINTROOM's current way of working (one exception chosen by the
  user on 2026-11-09, decision 22: in `solo` the reviewer runs as advice, `review.mode` = `advisory`).
- A skill lint script runs clean on the kit, the starter and PRINTROOM (name matches folder, "Use when"
  trigger, links resolve, no leftover placeholders), and an import resolver checks every `@path` in `CLAUDE.md`.
- A doc-size report prints the size (characters, rough tokens) of the always-loaded files, with a soft
  warning above 40,000 characters. PRINTROOM's `AGENTS.md` is NOT trimmed.
- `write-project-overview` creates an `AGENTS.md` in the PRINTROOM structure for a scratch project, and its
  refresh mode finds the stale statements in the starter.
- Test discipline is enforced: rule plus a test-edit guard hook (fix mode), proven by unit tests and one live block.
- Review gate: `REVIEW.md` template, a reviewer subagent told to change nothing, and a local pre-push gate that
  checks for a review record. (Changed 2026-11-09, decision 21: the GitHub branch-protection read was dropped.)
- Proven end to end: `update-workspace-kit` pull mode into the starter and PRINTROOM, `setup-workspace` on a
  scratch project, the starter's fresh-copy test, and a re-run of the playbook scorecard.

**Non-goals:** Claude in CI (evals, review) and any API key; Maintain-stage plays (control bands, Claude Tag);
managed settings and sandbox; parallel worktree workflow; any change to PRINTROOM app code in `src/`;
trimming PRINTROOM's `AGENTS.md`.

**Constraints:** local only; kit changes on a branch of the kit repo, the user pushes and merges; commits carry
changelog variables; moving content never deletes it; Windows paths; every control off by default unless the
profile turns it on, and Claude-run checks (`claude -p`) are opt-in because they use the user's Claude usage.

**Assumptions:** the user reviews every step on private projects (so formal gates are optional there); branch
protection can only be switched on by the user in GitHub; static checks cannot prove skill triggering.

**Top risks and mitigations:**
| Risk | Mitigation | Proof |
|---|---|---|
| Test-edit guard blocks a legitimate change | Fix mode only; blocks edits to test files that exist in git, allows new ones; marker expires (4 h) and is gitignored; fails open; a block says how to proceed; `ALLOW_TEST_EDITS=1` | Unit tests for 5 cases and one live block |
| A generated or shortened overview makes sessions worse | PRINTROOM's file is kept as is; the generator writes short, dated, one-fact bullets with verified/unverified marks; doc-size report is measure-only | Scratch-project run and the starter refresh |
| `@` imports in `CLAUDE.md` unverified | Static resolver (every `@path` must exist); optional `claude -p` check; `/memory` by hand | Resolver in the lint; check result recorded |
| Skill triggering cannot be proven without running Claude | Static lint; trigger fixtures; opt-in local runner; reports say "structure verified, triggering not verified" | Fixtures exist for every skill |

## Workflow profile (new, from the user's answers to rows 1, 5 and 6)

One file per project, `.claude/workflow.json`: `{ "profile": "solo", "overrides": { ... } }`. Precedence: environment
variable (for one command) > project overrides > profile default. A small pure module resolves it; hooks and
check scripts import it; skills read the file by instruction.
