# Rule: use the project's skills

For projects that have a router skill (`workspace-router`) this rule is already part of it. For projects
that do not, apply it directly.

1. When a task matches a skill's description, **read the whole skill before you start**. Do not work from
   its one-line description.
2. If several skills apply, read them in the order that goes from foundations to details.
3. Read each skill once per session, the first time its area comes up.
4. Never invent an API, flag or setting for a library without the skill content or the library's current
   documentation.
5. **Truth order (highest wins):** the project's files (manifests, config, source, hooks, CI) → the
   overview document → skill content read from disk → official live documentation → notes and memory.
